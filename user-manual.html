1 Introduction

Welcome to the UWU Smart Procurement System — an enterprise-grade platform designed to digitise and automate the entire procurement lifecycle for Uva Wellassa University.

What is this System?

The UWU Smart Procurement System is a web-based Software-as-a-Service (SaaS) application that manages procurement from initial need identification through to final payment and audit. It is built with AI-driven intelligence, role-based access control (RBAC) for 15 distinct user roles, and full compliance with Government of Sri Lanka (GOSL) National Procurement Agency (NPA) guidelines.

Key Capabilities

📋

End-to-End Procurement

From requisition creation to final payment — all 15 stages digitised in one platform.

🤖

AI Intelligence

Market price analysis, bid verification, risk assessment, and smart recommendations powered by Gemini AI.

🔐

15 User Roles

Granular role-based access control from Super Admin to Guest Viewer — each with tailored dashboards.

📊

Reports & Audit

Comprehensive audit trails, spend analysis, vendor performance tracking, and compliance reports.

📄

Document Management

Centralised repository for tender documents, contracts, invoices, and GRNs with cloud storage.

💬

Communications Hub

Built-in messaging between officers and vendors with real-time notifications.

2 Prerequisites

System requirements and what you need before using or hosting the application.

For End Users (Web Browser)

  • Browser: Google Chrome (v100+), Mozilla Firefox (v100+), Microsoft Edge (v100+), or Safari (v16+)
  • Screen Resolution: Minimum 1280×720 (responsive design supports mobile)
  • Internet Connection: Stable broadband connection
  • Credentials: Institutional email and password provided by your administrator

For Hosting / Developers

  • Node.js: v18 or later
  • npm: v9+ (comes with Node.js)
  • MongoDB: v6+ (local or MongoDB Atlas cloud)
  • Git: For version control
  • API Keys: Gemini AI API key, Cloudinary credentials, SMTP credentials

3 Installation & Setup

Step-by-step guide to set up the system from scratch on your machine or server.

1

Clone the Repository

Download the project source code using Git:

# Clone the repository
git clone https://github.com/your-org/smart-procurement-system.git
cd smart-procurement-system
2

Install Dependencies

Install all packages for both frontend and backend (monorepo):

# Install all dependencies at root (workspaces)
npm install
3

Configure Environment Variables

Copy the example environment file and fill in your credentials:

# Copy the example .env file
cp .env.example .env

Open the .env file and configure the following variables:

VariableDescriptionExample
MONGODB_URIMongoDB connection stringmongodb+srv://user:pass@cluster.mongodb.net/uwu_procurement
JWT_SECRETSecret key for JWT tokensyour-super-secret-key-here
GEMINI_API_KEYGoogle Gemini AI API keyAIza...
SMTP_HOSTEmail SMTP serversmtp.gmail.com
SMTP_USEREmail address for sendingnoreply@uwu.ac.lk
SMTP_PASSEmail password or App Passwordxxxx-xxxx-xxxx-xxxx
CLOUDINARY_CLOUD_NAMECloudinary cloud nameyour_cloud_name
CLIENT_URLFrontend URLhttp://localhost:5173
VITE_API_URLBackend API base URLhttp://localhost:5000/api/v1
4

Seed the Database (Optional)

Populate the database with demo users and sample data for testing:

# Seed 15 demo users and sample data
cd apps/api
node seed.js
5

Start Development Servers

Launch both the frontend and backend servers:

# Option 1: Start both servers (from project root)
npm run dev

# Option 2: Start individually
npm run dev:api   # Backend on port 5000
npm run dev:web   # Frontend on port 5173
6

Access the Application

Open your web browser and navigate to:

# Frontend (Web Application)
http://localhost:5173

# Backend API (for verification)
http://localhost:5000/api/v1
💡
Tip: When deploying to production, build the frontend with npm run build and serve the apps/web/dist folder with a web server like Nginx or deploy to Vercel/Netlify. The API can be deployed on services like Render, Railway, or AWS EC2.

5 User Roles (15 Roles)

The system enforces Role-Based Access Control (RBAC) with 15 distinct roles, each with tailored permissions and dashboards.

🔴 System & Administrative

Super Admin — Unrestricted Platform Access

Full unrestricted access to the entire platform. Manages SaaS settings, tenant onboarding, system configuration, and all modules. Can perform any action in the system.

Landing Page: Dashboard

Procurement Admin — Master Data & Workflow

University supplies division administrator. Manages Master Data, Standard Procurement Document (SPD) templates, DAPP management, and workflow routing rules.

Landing Page: Dashboard

🟣 Executive Leadership

Vice-Chancellor (VC) — Accounting Officer

The Accounting Officer (AO) with full read-access across all modules. Accesses Executive Dashboards, digitally signs high-value contracts and Letters of Award (LOA). Provides final approval for major procurements.

Landing Page: Dashboard

Faculty Dean — Faculty-Scoped Approvals

Faculty-scoped approval authority. Approves requisitions from their faculty, monitors Faculty Budget Utilisation. Can only see data scoped to their assigned faculty.

Landing Page: Dashboard

🔵 Finance & Budgetary Control

Chief Bursar — Financial Integrity

Ensures global financial integrity. Manages Financial Reconciliation, approves high-value budget commitments, and verifies the 3-way match (Purchase Order / Invoice / GRN).

Landing Page: Dashboard

Finance Committee — High-Value Oversight

High-level financial oversight committee. Reviews and approves large acquisitions that exceed threshold limits.

Landing Page: Dashboard

Finance Officer — Daily AP Operations

Handles daily Accounts Payable operations. Verifies budget codes (Vote Particulars), tax details, processes invoices, and disburses payments.

Landing Page: Dashboard

🟢 Procurement & Evaluation

Procurement Officer (PMD) — Tendering Lifecycle

Manages the complete tendering lifecycle. Drafts Standard Procurement Notices (SPN), manages the Digital Bid Box, coordinates Bid Opening Committee (BOC) activities, and oversees evaluations.

Landing Page: Dashboard

Contract Manager — CLM

Contract Lifecycle Management (CLM). Manages milestones, SLA compliance, performance security expiration alerts, and contract amendments.

Landing Page: Contracts

TEC Member — Technical Evaluation

Technical Evaluation Committee member. Uses the Technical Evaluation Workspace for assigned tenders. Has no access to financial data until the proper evaluation stage.

Landing Page: Evaluation

🟠 Departmental & User

Department Head — First-Level Approval

First level of institutional approval. Manages the Departmental Requisition Queue, verifies necessity and technical validity of requests from department users.

Landing Page: Approvals

Department User — Requisition Creator

Staff and lab coordinators. Uses the Procurement Intake Portal to draft requisitions, get AI specification suggestions from Gemini AI, and upload Bills of Quantities (BOQs).

Landing Page: Procurements

🩵 Operations & Logistics

Store Manager — Inventory & GRN

Manages Inventory & Logistics. Records physical receipt of goods, generates Goods Received Notes (GRN), updates asset inventory, and issues items to departments.

Landing Page: Delivery

🟤 External

Supplier — Vendor Portal

External Vendor Portal. Manages registration and KYC/CIDA certifications, submits bids to the Digital Bid Box, tracks payment status, and communicates with procurement officers.

Landing Page: Dashboard (Supplier-specific)

⚫ Oversight

System Auditor — Read-Only Compliance

Full read-only access to every module, decision log, and audit trail. Exports compliance reports and investigates AI-flagged anomalies. Cannot modify any data.

Landing Page: Reports

7 The 15-Stage Procurement Lifecycle

The complete GOSL-compliant procurement process from need identification to audit.

1
Requisition Phase

Need Identification & Requisition

Department User creates a procurement requisition specifying items, quantities, estimated costs, and justification.

2
Requisition Phase

Specification & BOQ Preparation

Detailed technical specifications and Bill of Quantities (BOQ) are prepared, with AI suggestions for specifications.

3
Approval Phase

Multi-Level Approval Chain

Request goes through Dept. Head → Dean → Procurement Officer → Bursar/VC based on value thresholds.

4
Finance Phase

Financial Validation & Budget Lock

Finance Officer verifies Vote Particulars, budget availability, and locks the committed budget amount.

5
Tender Phase

Procurement Strategy

Determine procurement method (NCB, ICB, Shopping, Direct) based on estimated value and NPA guidelines.

6
Tender Phase

Document Preparation & Solicitation

Standard Procurement Documents (SPD) prepared and tender notice published to registered vendors.

7
Bidding Phase

Secure Digital Bidding

Vendors submit sealed bids through the encrypted Digital Bid Box before the deadline.

8
Bidding Phase

Public Bid Opening

Bids are opened publicly by the Bid Opening Committee (BOC) with full audit logging.

9
Evaluation Phase

Technical & Financial Evaluation

TEC Members evaluate technical proposals; financial evaluation follows for technically qualified bidders.

10
Award Phase

Award Decision

Best-evaluated bid is selected and award recommendation prepared for approval authority.

11
Award Phase

Standstill Period & Appeals

Mandatory standstill period for unsuccessful bidders to request debriefing or submit appeals.

12
Contract Phase

Contract Finalization

Formal contract signed between university and awarded vendor with milestones and SLA terms.

13
Delivery Phase

Delivery & 3-Way Match

Goods received, GRN generated, and 3-way match performed (Purchase Order ↔ Invoice ↔ GRN).

14
Payment Phase

Payment Processing

Invoice verified, payment approved and disbursed to vendor through Accounts Payable.

15
Audit Phase

Reporting & Audit

Complete audit trail, spend analysis, vendor performance reports, and compliance verification.

8 Procurement (Requisitions)

Creating, managing, and tracking procurement requisitions.

Creating a New Requisition

Roles that can create requisitions: Department User Department Head Procurement Officer Admin

1

Navigate to Requisitions

Click "Requisitions" in the sidebar under Procurement Lifecycle, or click the green "+ New Requisition" button in the sidebar or top header.

2

Fill in Request Details

Complete the form with:

  • Title: Descriptive name for the procurement
  • Category: Goods, Works, or Services
  • Description: Detailed justification and specifications
  • Estimated Value: Total estimated cost in LKR
  • Priority: Low, Medium, High, or Urgent
  • Items: Add individual line items with quantities and unit prices
3

AI Market Price Analysis

Use the AI Market Price feature to get real-time market pricing suggestions for your items. The system compares your estimated prices with current market rates.

4

Submit for Approval

Click "Submit" to send the requisition through the approval chain. Track its status in the Requisitions list.

Viewing Requisition Details

Click on any requisition in the list to view its full details including:

  • Current approval status and chain progress
  • Item breakdown with quantities and prices
  • Attached documents and BOQs
  • AI risk assessment results
  • Approval history and comments

Editing a Requisition

Requisitions can be edited while in Draft or Returned status. Navigate to the requisition and click "Edit". Once submitted for approval, editing is locked.

9 Approvals

Multi-level approval workflow for procurement requisitions.

Roles with approval authority: Department Head Dean Procurement Officer Bursar Finance Committee Vice-Chancellor

Approval Queue

Navigate to "Approvals" in the sidebar. You'll see a queue of requisitions pending your approval action. Each item shows:

  • Requisition title and reference number
  • Requester name and department
  • Estimated value and category
  • Priority level and submission date
  • Current stage in the approval chain

Approving or Rejecting

1

Review the Request

Click on a pending request to view full details, attached documents, and AI analysis.

2

Take Action

Click "Approve" to advance the request to the next approver, or "Reject" to return it to the requester with comments. You can also "Return for Revision" with specific feedback.

Budget Lock

After all approvals are granted, the Finance Officer or Bursar verifies budget availability and locks the committed amount under the "Budget Lock" section. This ensures funds are reserved for the procurement.

10 Tendering

Managing the complete tender lifecycle from preparation to evaluation.

Bid Preparation (Creating Tenders)

Roles: Procurement Officer Admin

1

Navigate to Bid Preparation

Go to "Bid Preparation" under Tendering in the sidebar. Click "Create Tender".

2

Configure Tender Details

Link to an approved procurement request, set the tender method (NCB/ICB/Shopping), bid submission deadline, bid opening date, and evaluation criteria.

3

Publish the Tender

Once all documents are ready, publish the tender to make it visible to registered vendors in the Digital Bid Box.

Digital Bid Box

The Digital Bid Box is a secure, encrypted submission system. Vendors submit sealed bids before the deadline. No one can view bids until the official opening.

  • Supplier — Submit bids with technical and financial proposals
  • Procurement Officer — Manage bid box, monitor submission counts

Bid Opening

The Procurement Officer initiates the formal bid opening process. All bids are unsealed simultaneously with full audit logging.

Technical & Financial Evaluation

TEC Members access the Evaluation Workspace to:

  • Score technical proposals against predefined criteria
  • Review AI-powered bid verification results
  • Access AI Comparative Analysis for side-by-side bid comparison
  • View AI Smart Recommendations for vendor selection

11 Contracts

Award management, contract creation, and lifecycle tracking.

Award & Standstill

After evaluation, the Awards page shows the recommended winner. The system enforces a mandatory standstill period (configurable, default 10 days) during which unsuccessful bidders can:

  • Request a debriefing (within 3 days)
  • Submit a formal appeal

Creating a Contract

Navigate to "Contracts" → "New Contract". Link to the awarded tender and configure:

  • Contract value and payment terms
  • Milestones and deliverables
  • SLA requirements and penalties
  • Performance security details
  • Contract duration and renewal terms

Contract Details & Tracking

Each contract has a detailed view showing current status, milestone progress, delivery status, and linked payments. The Contract Manager receives alerts for:

  • Approaching milestone deadlines
  • Performance security expiration
  • SLA compliance breaches

12 Delivery & Payments

Goods receipt, 3-way matching, and payment processing.

3-Way Match (Delivery)

The 3-Way Match page ensures financial integrity by cross-referencing three documents:

  1. Purchase Order (PO): What was ordered
  2. Vendor Invoice: What the vendor billed
  3. Goods Received Note (GRN): What was actually received

Discrepancies are automatically flagged for review by the Finance Officer or Bursar.

Payment Processing

Navigate to "Payments" to view all pending and processed payments:

  • View payment details linked to contracts and invoices
  • Process payment approvals (Finance Officer/Bursar)
  • Track payment history and disbursement status
  • Suppliers can track their payment status through the Vendor Portal

22 Troubleshooting

Common issues and how to resolve them.

❌ Cannot log in — "Invalid credentials" error
  • Double-check your email address (institutional email format: username@uwu.ac.lk)
  • Ensure Caps Lock is not enabled
  • For demo accounts, use password: Demo@1234
  • If you forgot your password, click "Forgot Password?" on the login page
  • Contact your Super Admin if your account may be deactivated
🚫 "Access Restricted" — cannot access a module

Your user role does not have permission to access this module. The system enforces strict RBAC — each role only sees modules they're authorised to use. Contact your Admin if you believe you need access.

🔄 Page is loading indefinitely / API errors
  • Check if the backend API server is running (port 5000)
  • Verify your internet connection
  • Check the browser console (F12) for error messages
  • Clear browser cache and cookies, then try again
  • If hosting locally, ensure MongoDB is connected
📄 File upload fails
  • Ensure the file size is within the allowed limit
  • Accepted file formats: PDF, DOCX, XLSX, PNG, JPG
  • Check that Cloudinary credentials are properly configured in the .env file
  • Try a different browser if the issue persists
📧 Not receiving email notifications
  • Check your spam/junk folder
  • Verify SMTP settings in the .env file
  • Ensure SMTP_USER and SMTP_PASS are correct
  • For Gmail, you may need to use an App Password (not your regular password)
🤖 AI features are not working
  • Verify your GEMINI_API_KEY is valid and active
  • Check that the API key has sufficient quota/credits
  • Ensure the backend server can reach the Gemini API endpoint
  • Review API server logs for detailed error messages
🖥️ Development server won't start
  • Ensure Node.js v18+ is installed: node --version
  • Run npm install from the project root
  • Check that ports 5000 (API) and 5173 (Web) are not already in use
  • Verify the .env file exists and has valid MongoDB URI
  • Check MongoDB connection — ensure the Atlas cluster is accessible or local MongoDB is running
